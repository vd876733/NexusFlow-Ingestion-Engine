# 🚀 NexusFlow Ingestion Engine

A premium, real-time data engineering pipeline for ingesting and transforming high-throughput user engagement clickstreams into a modern Medallion Lakehouse architecture.

NexusFlow is designed for velocity, resilience, and observability: raw events are captured from Kafka-driven streams, validated into a robust Bronze landing zone, refined into a curated Silver layer, and aggregated into a Gold business metrics mart for instant reporting. A hyper-aesthetic Glassmorphic React dashboard provides a polished operational view of the entire data journey.

---

## ✨ PROJECT OVERVIEW

NexusFlow is a real-time streaming ingestion platform built to process massive user interaction clickstreams with enterprise-grade reliability. It combines distributed event streaming, scalable batch/stream processing, and a beautiful monitoring experience into a single, cohesive data platform.

### 🧰 Core Tech Stack

- Apache Spark Structured Streaming
- Python 3.14
- Kafka Protocols
- Columnar Parquet
- React
- Vite
- Tailwind CSS
- Recharts

### 🎯 What the project does

- Ingests mock or real-time clickstream events into Kafka
- Parses and validates event payloads with schema-aware handling
- Routes malformed records into a Dead Letter Queue (DLQ)
- Persists raw and curated data into a local Lakehouse structure
- Produces business-ready aggregates for analytics and monitoring
- Visualizes KPIs through a premium cyber-operations style dashboard

## 🏗️ ARCHITECTURE & DATA LIFECYCLE (THE MEDALLION PATTERN)

The pipeline follows the Medallion architecture pattern to keep data quality and governance increasing at each stage.

### 1) Bronze — Raw / Immutable Landing Zone

The Bronze layer is the first stop for incoming streaming data. It captures raw payloads in their original form and preserves them as immutable records for downstream replay and auditability.

Key characteristics:
- Stores incoming events as raw, validated landing data
- Maintains a DLQ for corrupt or malformed JSON payloads
- Prevents stream failure from bad records by isolating them safely
- Preserves the original event footprint for recovery and debugging

### 2) Silver — Enforced Enterprise Zone

The Silver layer cleanses and standardizes data for analytics consumption. It improves data quality through strict transformations and business-safe typing.

This is handled by the transformation script:

```bash
python silver_transform.py
```

Silver processing includes:
- Deduplication of event keys to avoid duplicate rows
- Strict type casting for improved consistency
- Partitioning by date blocks for efficient storage and query planning
- A curated, analytics-ready dataset for downstream use

### 3) Gold — Business Metrics Mart

The Gold layer is optimized for fast reporting and dashboard performance. It aggregates high-velocity event streams into hourly metrics such as:
- Event-type counts
- Unique user reach
- Conversion-style engagement patterns

This is generated by:

```bash
python gold_metrics.py
```

Gold data is designed to load instantly for monitoring, executive reporting, and near-real-time decision support.

## ⚡ QUICK START / HOW TO RUN

### Step 1 — Start the backend pipeline

From the repository root, run the Python-based data flow scripts:

```bash
python producer.py
python spark_streaming.py
python silver_transform.py
python gold_metrics.py
```

If your local Kafka broker is not running yet, start the infrastructure first:

```bash
docker compose up -d
```

### Step 2 — Launch the dashboard UI

Change into the frontend directory:

```bash
cd dashboard-ui
```

Install dependencies:

```bash
npm install
```

Start the development server:

```bash
npm run dev
```

Then open:

```text
http://localhost:5173/
```
